**Features & improvements**

- Add [custom intents](/projects/managed-settings/support/custom-intents/) through enterprise managed configuration for activities, broadcasts, services, and Android settings. Each entry starts disabled and must be enabled by the administrator. Custom intents do not require a licensed organisation ID.
- Support optional String, Boolean, Integer, and Long extras for custom intents. Invalid extras make the whole action unavailable.
- Add security patch, OS build, and uptime to activation reports.
- Keep custom-intent extra values out of activation reports and HTTP body logs.
- Disable app data backup and device transfer to keep configuration and device identity local to each device.

**Fixes**

- Fix cached country-code handling in activation reporting.
- Handle blocked APN launches without crashing MANAGED SETTINGS.
- Fix custom-intent icon theming and row alignment. Missing descriptions now show **No description provided**.
- Keep the toolbar colour neutral when scrolling.

**Known issues**

Some OEMs/devices do not support AOSP settings intents. APN settings can also return or fail inside the device's Settings app after a launch is accepted. Handling a blocked launch in MANAGED SETTINGS does not fix failures in the target Settings app.

OEM/device support and the reporting process are documented under [OEM support](/projects/managed-settings/support/oem-support/).
